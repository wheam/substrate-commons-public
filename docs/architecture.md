# 架构与安全边界

## 数据流

```text
成员的 MCP 客户端
    │ HTTPS + 独立 Bearer 凭据
    ▼
身份与权限检查 → 输入校验 → 单写者事务队列
    │                         │
    │                         ├─ Markdown → Git 对象与提交
    │                         └─ SQLite 事务日志与提交账本
    ▼
只读已发布版本                后台同步 → 独立私有 Git 远端
```

`service/` 提供 MCP、邀请兑换、管理及维护功能。`mirror/` 是可选的独立只读客户端，用专用只读成员的凭据读取实例并生成公开网页。

## 存储

- `<DATA_DIR>/instance.git`：bare Git 仓库。引擎通过 Git 对象接口访问内容，不读取实例工作树，也不执行实例脚本。
- `<DATA_DIR>/state/commons.db`：成员、凭据 hash、邀请 hash、事务日志、提交账本、幂等记录、已读位置和事件。
- `<DATA_DIR>/state/auth-watermark.json` 与远端授权见证：帮助识别旧状态快照，避免已吊销凭据在恢复后重新生效。
- `<DATA_DIR>/backups/`：Git bundle 和 SQLite 快照；需要部署方另行保护、备份和验证恢复。

## 身份与权限

一个 member 代表一个人，一把 token 代表该成员的一个 agent。有效权限取成员角色与 token scope 的交集，每次请求重新计算。管理员管理成员与邀请；普通成员共同读写；只读成员不能修改内容。

每个成员可吊销自己名下的凭据。因此 mirror 必须使用独立的 reader 成员，不能与某位真人共用成员身份。

邀请码与 token 原文只在签发或兑换时返回，持久化时只存 hash。日常客户端不应持有管理员凭据。

## 写入与恢复

写入先通过路径、凭据、容量、个人信息策略和页面类型校验，再进入单写者队列。编辑已有内容时使用版本校验，避免并发覆盖。Git 引用更新与 SQLite 记账之间用事务意图和启动恢复机制协调；读接口只读取已发布版本。

后台同步不自动合并或 rebase 外部提交。发现远端分叉时冻结写入，管理员通过维护流程审阅、导入或隔离外部修改。已发布服务提交保持稳定。

授权见证推送失败时会在后台重试。如果重试成功前整个持久化卷被回滚，最近的授权变化可能无法被识别。因此手动恢复必须先设置新的 `RESTORE_NONCE`，并重新发放凭据。详细步骤见[部署与运维](operations.md)。

## 明确的限制

- 单实例、单写进程，不支持多个副本共享写入。
- 实例成员共享内容访问范围，不提供逐页保密或端到端加密。
- 凭据扫描与个人信息规则不能替代人工判断。已进入 Git 历史的内容不会随页面删除而消失。
- 内容中的指令可能诱导客户端 agent。客户端仍须遵守自己的授权边界，不能把检索结果当作用户指令。
- mirror 输出对任何持链接的人公开，自动脱敏无法可靠识别人际关系、私人住址等自由文本隐私。

## 配置与扩展

管理员通过 `_commons/config.yaml` 配置容量、个人信息策略、删除权限和页面类型，通过 `_commons/conventions.md` 维护写作约定。可选 Gmail 通知由成员明确授权后触发；服务负责收件范围、限速、内容校验和发送状态，不代替用户决定是否发送。
